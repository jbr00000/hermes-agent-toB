# 联网检索接入方案（SearXNG + Firecrawl，浏览器兜底）

> 状态：方案已定稿，待实施
> 关联文档：`docs/前后端对接规划-不含知识库.md`（P2 条目"Web 检索"）、`docs/改造计划.md`
> 最后更新：2026-08-10

## 1. 目标与原则

让智能体具备"查资料并回答问题"的能力，同时守住 to-B 硬约束：

- **不出域**：搜索与抽取全部走客户部署内的自托管服务，不调用任何 SaaS API（Tavily/Exa 等云端 provider 不启用）。
- **最小改动**：仓库已内置完整的 web provider 插件体系，本方案只做"配置 + 接线"，不改核心文件。
- **能力分级**：搜索/正文抽取是主路径；浏览器自动化只作为"操作网站"场景的 P3 兜底，不为查资料服务。

## 2. 总体架构

```
用户提问
   │
   ▼
web_search（SearXNG，元搜索聚合）          ← 定位：答案在哪个网页
   │  返回 [{title, url, description} × N]
   ▼
web_extract（Firecrawl 自托管，渲染+正文清洗） ← 阅读：把网页正文拿回来
   │  返回 [{url, title, content(markdown)}]
   ▼
模型综合正文作答（正文经注入防护后进入上下文）

P3 兜底（仅"操作网站"类需求，本期不实施）：
browser_navigate 等浏览器工具（plugins/browser/browser_use，本地无头 Chromium）
```

### 为什么是两个组件而不是一个

| | SearXNG | Firecrawl |
|---|---|---|
| 输入 | 查询词 | 具体 URL |
| 输出 | 标题 + URL + 一两行摘要 | 完整正文（markdown，去广告/导航） |
| 本质 | 元搜索引擎（聚合上游引擎结果） | 网页抓取器（渲染 JS、抽取正文） |
| 短板 | 不抓页面内容 | 不能搜索 |

二者是串联关系：搜索管定位，抽取管阅读。SaaS 二合一方案（Tavily/Exa）因"不出域"约束排除。

## 3. 现状盘点（仓库已有件）

| 环节 | 已有件 | 说明 |
|---|---|---|
| 搜索 provider | `plugins/web/searxng/` | SearXNG JSON API 客户端，`SEARXNG_URL` 配置即启用，无需 key |
| 抽取 provider | `plugins/web/firecrawl/` | 自托管时设 `FIRECRAWL_API_URL`，无需 key；已内置跳转目标 SSRF 检查 |
| 工具注册 | `tools/web_tools.py` | `web_search`/`web_extract` 已注册；`check_fn=check_web_api_key`，未配置后端时工具自动对模型隐藏 |
| 工具集 | `toolsets.py` | 已有 `"web": ["web_search", "web_extract"]` |
| SSRF 防护 | `tools/url_safety.py` | 默认拦截内网/元数据地址（169.254.169.254 等永远拦截）；`security.allow_private_urls` 可显式放行 |
| 浏览器兜底 | `plugins/browser/browser_use` + `browser_navigate` 等 | P3 备用；工具描述内置"优先 web_search"引导（`model_tools.py:463`） |

**唯一缺口**：`server/tool_policy.py` 的 headless 工具策略目前只放行 `db`/`terminal`，`web` 工具集未接入。

## 4. 镜像构建方案

### 4.1 镜像清单

| 服务 | 镜像 | 作用 | 资源量级 |
|---|---|---|---|
| searxng | `searxng/searxng:<锁定tag>` | 元搜索引擎 | 极轻（~100MB，单容器） |
| firecrawl-api | `ghcr.io/mendableai/firecrawl:<锁定tag>` | 抓取 API + worker | 中 |
| firecrawl-playwright | `ghcr.io/mendableai/firecrawl-playwright:<锁定tag>` | JS 渲染微服务 | 重（含 Chromium，~1GB） |
| firecrawl-redis | `redis:7-alpine` | Firecrawl 队列 | 极轻 |

> Firecrawl 自托管的组件拆分以交付时官方 self-host compose 为准（历史上为 api/worker/playwright-service/redis 四件套）；上表按此列出，落地时核对官方仓库最新编排。

**版本锁定纪律**（对齐 AGENTS.md 依赖固定政策）：

- 交付镜像**禁止 `:latest`**，全部锁到具体 tag 或 digest（`image@sha256:...`）。
- 升级镜像 = 一次显式的交付动作：先在测试环境验证搜索/抽取回归，再改 tag。

### 4.2 联网环境：直接拉取

客户环境可访问公网镜像仓库时，直接在 `docker-compose.yml` 增加服务（见 §4.4），`docker compose pull && docker compose up -d` 即可。

### 4.3 离线/内网交付：镜像离线包（on-prem 常见）

客户环境完全离线时，在交付机上预构建离线包：

```bash
# 交付机（有网）执行：拉取并锁定版本后打包
docker pull searxng/searxng:<tag>
docker pull ghcr.io/mendableai/firecrawl:<tag>
docker pull ghcr.io/mendableai/firecrawl-playwright:<tag>
docker pull redis:7-alpine

docker save searxng/searxng:<tag> \
            ghcr.io/mendableai/firecrawl:<tag> \
            ghcr.io/mendableai/firecrawl-playwright:<tag> \
            redis:7-alpine | gzip > hermes-web-search-images-<版本>.tar.gz

# 客户现场（离线）执行：
gunzip -c hermes-web-search-images-<版本>.tar.gz | docker load
docker compose up -d
```

随包附带 `SHA256SUMS`（对 tar.gz 逐字节校验）与镜像 digest 清单，客户验收时比对。

### 4.4 compose 编排（含出网隔离）

核心安全设计：**检索组件挂独立的 `egress` 网络，够不到业务内网**；hermes 服务同时挂 `egress`（调 SearXNG/Firecrawl）和 `internal`（业务 DB 仍在 internal，检索容器不可达）。

```yaml
networks:
  internal:            # 既有：hermes + 业务 DB
  egress:              # 新增：仅检索组件 + hermes 的检索出口
    driver: bridge

services:
  searxng:
    image: searxng/searxng:<锁定tag>
    networks: [egress]
    volumes:
      - ./deploy/searxng:/etc/searxng:rw
    restart: unless-stopped

  firecrawl-api:
    image: ghcr.io/mendableai/firecrawl:<锁定tag>
    networks: [egress]
    environment:
      - REDIS_URL=redis://firecrawl-redis:6379
      - PLAYWRIGHT_MICROSERVICE_URL=http://firecrawl-playwright:3000
      - USE_DB_AUTHENTICATION=false
      # 其余 worker/队列变量以官方 self-host 文档为准
    depends_on: [firecrawl-redis, firecrawl-playwright]
    restart: unless-stopped

  firecrawl-playwright:
    image: ghcr.io/mendableai/firecrawl-playwright:<锁定tag>
    networks: [egress]
    restart: unless-stopped

  firecrawl-redis:
    image: redis:7-alpine
    networks: [egress]
    restart: unless-stopped

  hermes:               # 既有服务，追加 egress 网络
    networks: [internal, egress]
```

> 进一步收紧可在客户防火墙上只对 egress 网段放行 443 出向；SearXNG 侧还可在 settings.yml 里按需裁剪上游引擎列表（客户网络策略禁止的引擎直接关掉）。

### 4.5 SearXNG 配置（必做）

`deploy/searxng/settings.yml` 关键项：

```yaml
search:
  formats:
    - html
    - json        # ⚠️ 必须显式开启：provider 调 /search?format=json，默认配置只开 html，不开则 403

server:
  limiter: false  # 容器内网服务，关闭限流插件（或按客户策略配置）

ui:
  static_use_hash: true
```

### 4.6 可选：自建镜像（供应链管控更严的客户）

如对第三方镜像有审计要求，可用 Dockerfile 二次封装（固定 base digest + 打入客户证书/代理配置）：

```dockerfile
FROM searxng/searxng@sha256:<digest>
COPY settings.yml /etc/searxng/settings.yml
```

## 5. 配置接线（对 hermes 侧的改动）

全部改动均为配置 + 一行策略代码，不触碰核心文件：

**① `$HERMES_HOME/.env` 追加**（沿用上游既有配置键，非新增 HERMES_* 变量）：

```bash
SEARXNG_URL=http://searxng:8080
FIRECRAWL_API_URL=http://firecrawl-api:3002
```

**② `$HERMES_HOME/config.yaml` 追加**：

```yaml
web:
  backend: searxng            # 搜索后端（web.search_backend 的共享回退）
  extract_backend: firecrawl  # 抽取后端
```

**③ `server/tool_policy.py`**（唯一代码改动）：

```python
if normalized_mode in {"chat", "plan"}:
    return ["db", "web"]            # Chat/Plan 只读检索，符合 Chat 只读定位
if permission_mode == "full":
    return ["db", "terminal", "web"]
return ["db", "web"]
```

门控逻辑自动生效：未配置 `SEARXNG_URL`/`FIRECRAWL_API_URL` 时 `check_fn` 不通过，工具不出现在 schema 里，模型不会幻觉调用。工具集在每次 `/chat` 请求构建 AIAgent 时解析，无会话中切换，不违反 prompt caching 不变量。

## 6. 安全设计

1. **SSRF**：抽取环节的抓取目标不可信。两道防线：①`tools/url_safety.py` 默认拦截内网/元数据地址（保持默认，不要开 `security.allow_private_urls`）；②compose 网络隔离（§4.4），即使绕过应用层检查，检索容器也够不到业务网段。
2. **Prompt injection**：网页正文是不可信输入。接入时验证 `web_extract` 结果经过 `agent/message_sanitization.py` 的边界标记/清洗路径后再进上下文。
3. **审计**：搜索与抽取属于"外部访问"，需进入 `server/audit.py` 审计流（query、URL、时间、user_id）。落地时以一次真实调用验证审计记录完整。
4. **用量与超时**：沿用工具默认 limit/char_limit；SearXNG 上游引擎超时在 settings.yml 收敛，避免长尾请求拖住 agent loop。
