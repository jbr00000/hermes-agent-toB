# Cortex Agent 后续迭代计划

## 1. 目标与范围

本计划面向当前 to-B 版本 Cortex Agent，目标是把已经具备的 Chat、Agent、权限和 Docker 沙盒能力逐步收敛为可部署、可恢复、可审计的企业工作台。

当前范围不包含知识库解析、向量检索和知识库构建后端。知识库只保留前端入口，后续结合独立的文档解析与知识库算法方案另行设计。多媒体、语音、图片/视频及浏览器自动化工具继续保留，但扩展接入排在核心任务闭环之后。

## 2. 总体优先级

| 阶段 | 主题 | 优先级 | 交付结果 |
|---|---|---:|---|
| 一 | Agent 持久执行与故障恢复 | P0 | API 与执行进程分离，任务不因页面断开或 API 重启而丢失 |
| 二 | 任务文件与产物 | P0 | 文件可上传到任务工作区，结果可预览、下载、删除和审计 |
| 三 | 权限与审批闭环 | P0 | 风险分级、计划审批、临时权限和每次写操作校验形成闭环 |
| 四 | Agent 前端运行体验 | P1 | 完整展示排队、规划、审批、执行、失败、重试和工具时间线 |
| 五 | 沙盒生产运维 | P1 | 镜像、网络、并发、磁盘、清理和监控策略可运营 |
| 六 | 部署与可观测性 | P1 | 迁移、备份、日志、指标、告警和 CI 冒烟测试齐备 |
| 七 | 扩展工具与知识库 | P2 | 按业务需求接入多媒体、浏览器自动化及独立知识库后端 |

## 3. 阶段一：Agent 持久执行与故障恢复

### 3.1 目标架构

```text
Web 前端
  │ HTTP + SSE
  ▼
FastAPI Server ──写入──> MySQL（任务、运行、消息、审计）
  │
  └──入队/订阅──> Redis（队列、租约、心跳、取消、事件、回答快照）
                         │
                         ▼
                   Agent Worker
                         │
                         └──> AIAgent / Docker 沙盒 / 企业工具
```

### 3.2 本轮已完成

- Agent 的 Plan、Execute 和 Retry 请求改为 API 入队、Worker 执行。
- 同一应用镜像支持 `hermes-server` 与 `hermes-worker` 两种启动角色，无需新增应用镜像。
- Redis 增加持久任务队列、幂等入队、领取租约、Worker 心跳、取消标记、事件缓冲和完整回答快照。
- MySQL 的 `task_runs` 保存可恢复请求载荷、Worker 标识和心跳时间。
- 页面或 SSE 断开不会取消任务；前端可通过运行事件接口重新订阅。
- Worker 异常时，规划任务可自动回队；已开始执行的任务不会自动重放，避免数据库写入或外部操作重复执行，任务会失败并要求用户显式重试。
- Worker 领取 Execute 任务时重新校验权限租约，过期权限不会随队列任务继续生效。
- Agent 运行有默认 300 秒协作式超时，并持续更新 Redis 租约与 MySQL 心跳；不响应中断的调用将在后续通过子进程实现硬超时。
- Compose 增加独立 `hermes-worker` 服务，健康接口增加 Worker 状态。

### 3.3 后续增强

- 增加任务级指数退避、最大排队时长和租户优先级。
- 将不响应中断的模型调用放入可强制终止的子进程，形成硬超时边界。
- 增加 Worker 并发槽位和按租户/用户的公平调度。
- 增加运维侧死信队列、人工重新入队和失败原因分类。

## 4. 阶段二：任务文件与产物

- 增加任务附件上传、文件名规范化、媒体类型和大小校验、哈希去重。
- 将附件映射到任务专属沙盒工作区，不允许客户端提交任意宿主机路径。
- 扫描任务工作区生成产物清单，记录名称、大小、类型、哈希、来源运行和过期时间。
- 提供预览、下载、删除接口，并记录审计事件。
- 单机交付先使用受控本地目录；多节点部署再引入 MinIO 或兼容 S3 的对象存储。
- 此阶段只负责文件流转，不实现知识库解析和向量化。

## 5. 阶段三：权限与审批闭环

- 为工具定义 `read`、`controlled_write`、`high_risk` 风险等级。
- Plan 阶段固定只读；Execute 阶段必须存在已批准计划。
- 写操作除计划批准外，还必须具有左下角权限控件授予的有效临时租约。
- 在每一次工具调用前服务端重新校验用户、租户、任务、计划版本、权限模式和过期时间。
- 高风险动作支持逐次确认，权限自动过期、手动撤销，任务结束后强制恢复只读。
- 审计记录批准人、计划版本、权限变化、工具参数摘要、结果状态和关联产物。

## 6. 阶段四：Agent 前端运行体验

- 任务状态统一为：草稿、排队、规划、待审批、待执行、运行、完成、失败、取消。
- 增加计划版本对比、审批结果、权限到期提示和重新授权流程。
- 工具时间线展示开始、进度、完成、失败、耗时和可见的安全参数摘要。
- 增加取消、失败重试、Worker 中断说明、断线恢复和结果产物区域。
- 保持 Agent 与 Chat 的历史记录、Tab 状态和滚动位置相互独立。

## 7. 阶段五：沙盒生产运维

- 固定沙盒镜像白名单和镜像摘要，禁止运行未审批镜像。
- 配置租户、用户和节点级并发上限、CPU、内存、PID、运行时长与磁盘配额。
- 增加工作区保留周期、孤儿容器和过期目录定时清理。
- 当前 `allowlist` 网络策略继续默认拒绝；引入 Envoy、Squid 或专用出口代理后再实现真实域名白名单。
- 监控容器创建失败、超时、OOM、磁盘使用和清理结果。

## 8. 阶段六：部署与可观测性

- 生产启动统一执行 Alembic 迁移并记录版本，禁止使用 `create_all` 代替迁移。
- 增加 MySQL、Redis、任务文件和配置的备份恢复演练。
- 日志统一为结构化格式，贯穿 `tenant_id/user_id/task_id/run_id/request_id`。
- 提供任务队列长度、等待时间、运行时长、成功率、取消率、Worker 心跳和沙盒资源指标。
- 接入 Prometheus/Grafana 或企业现有监控平台，并为 Worker 缺失、队列堆积和连续失败配置告警。
- CI 增加迁移校验、Server/Worker 联合冒烟、前端断线恢复和 Docker 沙盒验证。

## 9. 阶段七：扩展能力

- 按业务优先级接入语音输入输出、图片/视频处理和浏览器自动化。
- 所有扩展工具必须先纳入风险分级、权限校验、沙盒边界和审计协议。
- 知识库后端待独立方案确认后接入，不与当前任务文件模块强耦合。

## 10. 建议的下一批开发顺序

1. 任务附件上传与沙盒工作区映射。
2. 产物登记、预览、下载和删除。
3. 工具风险分级与运行时权限校验。
4. Agent 前端工具时间线、失败原因和重试交互。
5. 沙盒网络白名单代理、并发和磁盘治理。
6. 监控、告警、备份与 CI 联合冒烟。
