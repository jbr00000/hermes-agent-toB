# Hermes Agent to-B 前后端对接规划（不含知识库）

> 目标：把 `apps/web` 当前 Mock 前端与 Hermes to-B 后端及智能体核心能力对接。本文不规划业务空间、知识库、文档解析、文档权限和知识库引用，这些能力保持 Mock，等待单独设计。

> **更新（2026-08）**：知识库已单独立项并实现一期（企业统一知识库构建：上传→解析→分块→ES/Milvus 入库，不含 RAG），见 [`知识库构建方案.md`](知识库构建方案.md)。本文其余部分仍不涉及知识库。

## 1. 核心结论

当前代码已经具备一批可直接复用的后端和算法能力：JWT 鉴权、用户隔离、SSE 流式回答、会话持久化、上下文恢复、计划审批状态、只读数据库查询、Docker 沙盒执行、个人记忆、用户管理、运行特性读取和内部审计记录。

但不能把前端直接从 `mockApi` 全量切换到现有 `/chat`，主要原因是：

1. 后端尚未区分产品层的 `Chat` 和 `Agent`，当前 `/chat` 默认进入 `execute`。
2. 前端的“只读 / 受控写入 / 完全访问”只存在于 UI，后端没有任务级授权状态。
3. 后端没有任务状态、取消、重试、断线恢复和结果产物接口。
4. SSE 只有文本事件，Agent 核心已有工具回调，但尚未桥接成结构化前端事件。
5. 审计数据已经写入 `audit.db`，但没有查询路由。
6. 前端和后端分端口开发时没有 CORS 配置；生产环境应优先采用同源反向代理。

因此建议先建立一个稳定的 BFF 接口层，前端只依赖类型化接口，不直接理解 `AIAgent`、toolset 或 SQLite 的内部结构。

## 2. 概念必须分开

| 概念 | 可选值 | 含义 | 当前后端状态 |
|---|---|---|---|
| 产品交互类型 | `chat` / `agent` | 用户是在问答，还是要求系统完成任务 | 尚未持久化 |
| Agent 执行阶段 | `plan` / `execute` | Agent 是生成计划还是执行计划 | 已实现 |
| 任务权限模式 | `read` / `controlled` / `full` | 当前任务允许产生何种副作用 | 尚未实现 |
| 任务运行状态 | `queued` / `running` / `waiting_approval` / `completed` / `failed` / `cancelled` | 长任务生命周期 | 尚未实现 |

不要继续复用一个 `mode` 字段表达以上四件事。建议保留现有 `mode=plan|execute` 的兼容含义，新增 `interaction_type` 和服务端 `permission_mode`。

## 4. Chat 与 Agent 的服务端策略

| 模式 | 默认工具能力 | 禁止能力 | 前端展示 |
|---|---|---|---|
| Chat | 模型问答、会话搜索、只读 DB；后续可选 Web/视觉 | terminal、文件写入、浏览器操作、可写 MCP、外部系统变更 | 文本流、来源、只读标记 |
| Agent + read | Chat 能力、计划生成、只读文件 | 所有写入和命令执行 | 计划、风险、只读上下文 |
| Agent + controlled | 任务 workspace 内生成结果、个人记忆、媒体产物 | 宿主机访问、数据库写入、跨任务路径、可写外部系统 | 产物、工具过程、任务状态 |
| Agent + full | 经策略批准的 terminal、浏览器、可写 MCP 等 | 策略明确禁止的系统级操作 | 审批、授权到期、完整审计 |

必须先修复两个安全不一致：

1. 当前 `/chat` 默认 `execute`，且 execute 默认带 `terminal`，不能用于前端 Chat。
2. 当前启用的 MCP toolset 会直接追加到 plan/execute toolsets；如果 MCP 内含写操作，会绕过“plan 只读”的产品语义。

## 5. 推荐的后端领域模型

保留 `Session` 作为模型对话上下文，同时新增面向业务执行的对象：

```text
User
 ├─ Conversation ── 对应 Chat，关联一个 Session
 └─ Task ────────── 对应 Agent，关联一个 Session
      ├─ TaskRun    一次执行或重试
      ├─ Plan       执行计划与审批状态
      ├─ PermissionLease  当前任务临时权限
      └─ Artifact   输出文件或媒体结果
```

第一阶段不必立即迁移 SQLite 主表。可以先给 headless session 增加 `interaction_type` 元数据；Task/TaskRun 在异步执行阶段再建独立表。

## 6. 推荐接口层

### 6.1 保留并直接使用

- `GET /health`
- `POST /auth/login`
- `GET /auth/me`
- `GET/POST/DELETE/PUT /users`
- `GET/POST/DELETE /memory`
- `GET/POST/DELETE /memory/candidates`
- `GET /sessions`
- `GET /sessions/{id}`
- `POST /sessions/{id}/resume`
- `GET/POST /sessions/{id}/mode|plan|approve|execute`

### 6.2 第一批扩展

| 接口 | 用途 |
|---|---|
| `POST /chat` 增加 `interaction_type` | 服务端区分 Chat 和 Agent，不允许客户端绕过工具策略 |
| `GET /sessions?interaction_type=chat|agent` | 分别驱动左侧问答列表和任务列表 |
| `PATCH /sessions/{id}` | 修改标题、归档和置顶状态 |
| `GET /runtime` | 返回 provider、model、sandbox、网络和工具策略摘要 |
| `GET /audit/events` | 驱动审计中心，支持分页和条件筛选 |

### 6.3 Agent 任务接口

| 接口 | 用途 |
|---|---|
| `POST /tasks` | 创建 Agent 任务，可带 `source_session_id` 承接 Chat 上下文 |
| `GET /tasks`、`GET /tasks/{id}` | 列表、状态、计划、产物和执行轨迹 |
| `PUT /tasks/{id}/permission` | 设置任务级临时权限，返回授权到期时间 |
| `POST /tasks/{id}/approve` | 审批当前计划 |
| `POST /tasks/{id}/execute` | 执行已审批计划 |
| `POST /tasks/{id}/cancel` | 调用运行中 Agent 的 interrupt |
| `POST /tasks/{id}/retry` | 创建新的 TaskRun，不覆盖失败记录 |
| `GET /tasks/{id}/events` | SSE 重连和历史事件补发 |

### 6.4 文件、产物和媒体接口

- `POST /tasks/{id}/files`
- `GET /tasks/{id}/files`
- `GET /artifacts/{artifact_id}`
- `POST /media/transcriptions`
- `POST /media/speech`

这些接口只规划临时任务文件和结果产物，不包含知识库入库与解析。

## 7. SSE 事件协议

现有 `delta/final/error/done` 可以保持兼容，新增结构化事件：

| 事件 | 前端用途 |
|---|---|
| `session.started` | 新会话立即取得 ID，不必等到流结束 |
| `message.delta` | 文本流式渲染 |
| `tool.started` | 展示工具名称、风险级别和开始时间 |
| `tool.progress` | 长命令、浏览器或媒体任务进度 |
| `tool.completed` | 展示成功、失败和耗时，不下发敏感原始参数 |
| `plan.required` | 展示执行计划并进入待审批状态 |
| `permission.required` | 提示所需权限，但不自动提权 |
| `task.status` | 更新 queued/running/waiting/completed 等状态 |
| `artifact.created` | 右侧结果区增加可下载产物 |
| `title.updated` | 更新左侧会话名和 Tab 标题 |
| `error` / `done` | 终止流并完成状态收敛 |

Agent 核心已有工具开始、进度、完成、状态和事件回调，后端主要工作是把它们转换成稳定 DTO，而不是让前端消费 Agent 内部对象。

## 8. 前端改造建议

不要把所有真实请求继续堆在一个 `mockApi.ts`。建议建立以下接口模块：

```text
apps/web/src/api/
  client.ts          JWT、错误映射、401、请求 ID
  auth.ts
  sessions.ts
  chat-stream.ts
  tasks.ts
  memory.ts
  users.ts
  runtime.ts
  audit.ts
  files.ts
  media.ts
```

TanStack Query 管理列表和详情；SSE 使用独立的 stream controller；Jotai 只管理 Tab、草稿、当前权限显示等 UI 状态。服务端权限不能以 Jotai 状态为准。

开发环境建议由 Vite `/api` proxy 转发到 FastAPI；生产环境由 Nginx/Ingress 将前端和 `/api` 放在同一域名，避免开放宽泛 CORS。

## 9. 分阶段实施顺序

### 阶段 A：连接基础设施与直接接口（P0）

- 建立统一 `apiClient`、环境配置、Vite proxy 和错误模型。
- 实现登录、当前用户、退出和路由保护。
- 接入用户管理、记忆中心、健康状态和会话详情。
- 增加契约测试，固定后端响应 DTO。

### 阶段 B：Chat 真正只读化（P0）

- 增加并持久化 `interaction_type=chat`。
- 新建 Chat 专用服务端工具策略。
- 接入 SSE 文本流、会话历史和恢复。
- 接入只读 DB；确认任何提示词都无法获得 terminal、写工具或可写 MCP。

### 阶段 C：Agent 计划与执行 MVP（P0）

- 增加 `interaction_type=agent`。
- 接入 plan、approve、execute 状态机。
- 实现服务端三档权限和任务内自动降权。
- 把当前前端计划条、权限切换和右侧状态改成服务端驱动。

### 阶段 D：任务、工具事件和产物（P1）

- 新增 Task/TaskRun、取消、重试和状态恢复。
- 桥接工具回调为结构化 SSE。
- 建立任务 workspace、附件和 Artifact 下载。
- Chat“转为任务”创建 Task，并继承允许传递的上下文引用。

### 阶段 E：管理与扩展能力（P1/P2）

- 开放脱敏审计查询。
- 接入 runtime/security 页面。
- 完成 MCP 风险分类。
- 再按客户需要开放 Web、浏览器、语音、视觉、图片和视频能力。

## 10. 验收底线

1. 不同用户不能读取或恢复对方的会话、任务、记忆和产物。
2. Chat 在任何提示下都不能调用 terminal、写工具或可写 MCP。
3. Agent 高风险执行必须同时满足计划审批和有效权限租约。
4. 完全访问在任务完成、失败、取消、超时或切换任务后自动失效。
5. 页面刷新或 SSE 断线后可以恢复任务状态，不重复执行工具。
6. 工具参数、数据库内容、密码和 token 不进入审计明文。
7. 所有任务结果只能写入任务 workspace，并通过 Artifact 接口下载。
8. 后端鉴权和工具策略是最终裁决者，前端隐藏按钮不构成安全控制。

## 11. 本轮明确不包含

- 业务空间模型。
- 知识库列表、检索、入库和构建。
- 文档解析与 chunk 管理。
- 空间、知识库和文档级权限。
- Chat 右侧“知识来源”的真实数据对接。

这些能力继续使用前端 Mock，后续单独设计接口和权限模型。
